# 生产架构与有界路由

对应源文档页码：15-16。本笔记为独立学习改编。

## 要理解的机制

文档证据与权威业务事实走两条路径。只读工具白名单由程序执行，证据中的命令不改变权限。先检查缺参数，再调用工具；当前 API 不可用时不使用文档旧数字替代。EvidenceBundle 应明确事实、来源和未知。

## 可运行实验

```bash
uv run rag-lab ask "订单 00001234 现在到哪一步"
uv run pytest -k "Q43 or Q48 or auth_outage"
```

## 验证与观察

检查路由、fact、evidence 和 trace 字段。权限服务故障必须在业务调用之前失败关闭。

## 进阶练习与边界

实现 HTTP 网关前加 schema、总 deadline、取消、扇出与重试预算；默认无自主 Agent、无 SQL/shell 写入能力。

## 自测

1. 哪种失败不能通过更强的检索模型修复？
2. 本实验锁定了哪些条件，还缺少哪些真实业务证据？
3. 如果撤权、超时或来源冲突发生在这一阶段，应怎样输出？
