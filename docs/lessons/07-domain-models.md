# 商品、菜单、订单与 CMDB

对应源文档页码：17-19。本笔记为独立学习改编。

## 要理解的机制

商品概念和售卖规格不能合并。渠道菜单、临时库存和同步水位是不同事实。支付、履约、退款各有状态；已受理不等于已到账。CMDB 图包含方向、环境和来源，缺边不证明零影响。

## 可运行实验

```bash
uv run pytest tests/test_document_regressions.py -k "Q25 or Q26 or Q27 or Q28 or Q29 or Q31 or Q32 or Q33"
```

## 验证与观察

同一 POSKEY 可跨渠道出现；同名服务在 prod/test 不能合并。两跳图遍历受到节点预算限制。

## 进阶练习与边界

接真实服务前定义 owner、字段脱敏、观测时间、价格有效期和历史支持契约；例子中的业务价格都是合成值。

## 自测

1. 哪种失败不能通过更强的检索模型修复？
2. 本实验锁定了哪些条件，还缺少哪些真实业务证据？
3. 如果撤权、超时或来源冲突发生在这一阶段，应怎样输出？
