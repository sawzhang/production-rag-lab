# 可观测性、故障与知识运营

对应源文档页码：28-29。本笔记为独立学习改编。

## 要理解的机制

Trace 保留阶段候选 ID、模型版本、generation、路由、延迟和降级，不默认写入原始私密文档。索引落后、模型故障和撤权不同步是三类不同事故。模型回滚不回滚删除账本。

## 可运行实验

```bash
uv run pytest -k "Q24 or Q43 or Q46 or ledger or generation"
```

## 验证与观察

从失败阶段选择修数据、修路由、修排序还是修答案约束。当前 trace 只在本机返回；部署后必须定义访问和保留期限。

## 进阶练习与边界

将业务 owner、接入 owner、平台、QA、SRE 的责任落到真实人员；接入水位、失败队列和源对账属于生产补充任务。

## 自测

1. 哪种失败不能通过更强的检索模型修复？
2. 本实验锁定了哪些条件，还缺少哪些真实业务证据？
3. 如果撤权、超时或来源冲突发生在这一阶段，应怎样输出？
